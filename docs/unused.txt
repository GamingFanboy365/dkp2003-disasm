Unused code and data in Diddy Kong Pilot (2003 build)
======================================================

Generated by tools/unused.py; its header describes the method.  Offsets
are ROM offsets (add 0x08000000 for the address); code that runs from
IWRAM is listed at its run-time address.  Only offsets, sizes, names and
short identifying debug strings are listed, no game content.

"Unused" means that nothing the game can reach from power-on refers to
it: no call, branch or pointer, also counting raw bytes the disassembly
has not decoded yet.
The result was checked against an mGBA run that records the executed
code (boot, intro movie, menus and 40 s of racing with items on Steamy
Swoop); none of the functions listed here ran.  The run is in
tools/emu (DKP_COVER=<file> repro_zinger_buzz.py).

8. Notes on the analysis
------------------------
  * Code copied to RAM is mapped to its run-time address: text32 at
    0x03000000, the audio engine at 0x03006498, and two ARM overlays
    (0x03C5C4 and 0x03DC1C in ROM) that game_init copies to 0x03003FC8.
  * Sprite level-of-detail sets stored after a sprite (NNN_2, ...) are
    reached by stepping over the previous container, not by a pointer;
    the trace in mGBA shows the decoder reading them.
